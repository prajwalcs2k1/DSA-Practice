## 🔍 What operations are happening?

You are doing:

1. **Level Order Traversal (BFS)** → visits each node once
2. For each node:

   * Insert into a **`map<int, vector<int>>`**

---

## ⚙️ Breaking down complexity

### 1. BFS Traversal

* Each node is processed exactly once
  👉 Cost = **O(N)**

---

### 2. Map Insertion

You are using:

```cpp
map<int, vector<int>> mp;
```

* `map` in C++ is a **Red-Black Tree**
* Insertion cost = **O(log K)**
  where `K` = number of unique verticals

👉 In worst case:

* `K` can be **O(N)** (skewed tree)

So:

* Each insertion → **O(log N)**
* Total insertions → **N**

👉 Cost = **O(N log N)**

---

### 3. Display Function

```cpp
for(auto &it : mp)
    for(auto ele : it.second)
```

* You traverse all nodes again
  👉 Cost = **O(N)**

---

## ✅ Final Time Complexity

```
O(N log N)
```

---

## ⚡ Space Complexity

* Queue (BFS) → **O(N)**
* Map storing all nodes → **O(N)**

👉 Final:

```
O(N)
```

---

## 🚀 Optimization Insight (important for interviews)

If instead of `map`, you used:

```cpp
unordered_map<int, vector<int>>
```

Then:

* Insertion → **O(1)** average
* But you'd need to track `minHD` and `maxHD` separately to print in order

👉 Optimized Time Complexity:

```
O(N)
```

---

## 🧠 Key Takeaway

* Your logic is correct
* The only reason it's **O(N log N)** is because of `map`
* This is a **classic interview trade-off**:

  * `map` → sorted automatically, slower
  * `unordered_map` → faster, but needs extra handling
