You said:

* Do inorder traversal → visits all `N` nodes
* For every node, do a BST search for `K - node->val`

So the actual complexity becomes:

[
O(N) \times O(H)
]

where:

* `H = height of BST`

Now depending on the tree:

* **Balanced BST** → `H = log N`

  * T.C. = `O(N log N)`

* **Skewed BST** → `H = N`

  * T.C. = `O(N^2)`

So your analysis should be:

```text
Average / balanced BST : O(N log N)
Worst case             : O(N^2)
```

NOT `O(N) * O(log(H))`.

Because BST search complexity is `O(H)`, not `O(log H)`.

---

There is also a better approach:

### Optimal Approach

* Use inorder traversal + hashset
* For every node:

  * check if `K - node->val` exists in set
  * else insert current value

Complexities:

* Time: `O(N)`
* Space: `O(N)`

---

There is an even more BST-specific optimal approach:

### Best BST Approach

Use:

* one inorder iterator (smallest → largest)
* one reverse inorder iterator (largest → smallest)

Exactly like two pointers in sorted array.

Complexities:

* Time: `O(N)`
* Space: `O(H)`

This is considered the most elegant BST solution.
