If you are creating a BST from a preorder traversal array, the time complexity depends on the approach used.

## 1. Naive Approach — Insert one by one into BST

For every element in preorder:

* Insert it into the BST using normal BST insertion.

### Time Complexity

* Each insertion takes:

  * **O(log n)** on average
  * **O(n)** in worst case (skewed tree)

So total:

* **Average Case:** `O(n log n)`
* **Worst Case:** `O(n²)`

Example worst case:

```txt
preorder = [1,2,3,4,5]
```

This creates a completely skewed BST.

---

## 2. Optimal Approach — Using Bounds (Recursive)

This is the standard efficient method.

Idea:

* Maintain an index in preorder.
* Use lower/upper bounds to decide whether a node belongs to the current subtree.
* Every element is processed exactly once.

### Time Complexity

* Each node is visited once.
* No repeated searching/insertion.

So:

* **Time Complexity:** `O(n)`
* **Space Complexity:** `O(h)`

  * `h = height of tree`
  * Worst case: `O(n)`
  * Balanced BST: `O(log n)`

Example efficient code structure:

```cpp
TreeNode* build(vector<int>& pre, int& i, int bound){
    if(i == pre.size() || pre[i] > bound)
        return NULL;

    TreeNode* root = new TreeNode(pre[i++]);

    root->left = build(pre, i, root->val);
    root->right = build(pre, i, bound);

    return root;
}
```

So the optimal preorder-to-BST construction runs in:

```txt
T.C = O(n)
```
