Your solution runs in **O(n²)** time. Here’s *why*, step by step—no hand-waving.

---

## 🔍 Outer loop

```cpp
for(int i = 0; i < n; i++)
```

This runs **n times**.

---

## 🔁 Work done for each `i`

For every index `i`, you do **two while loops**:

### 1. Scan left

```cpp
while(j >= 0 && arr[j] >= arr[i]) j--;
```

In the worst case (e.g., all elements are equal or increasing), this loop can go all the way to index `0`.

👉 Cost: **O(n)**

---

### 2. Scan right

```cpp
while(j < n && arr[j] >= arr[i]) j++;
```

Similarly, this can go all the way to index `n-1`.

👉 Cost: **O(n)**

---

## 📊 Total per iteration

For each `i`:

```
O(n) (left scan) + O(n) (right scan) = O(n)
```

---

## 🔥 Overall time complexity

Since this happens for every `i`:

```
n * O(n) = O(n²)
```

---

## 🧠 Intuition (important)

You are **repeating work**.

Example idea:

* For `i = 3`, you scan left over elements
* For `i = 4`, you again scan almost the same elements
* Same regions get scanned multiple times

👉 That repetition is what makes it **quadratic**

---

## ⚠️ Worst-case example

```cpp
arr = {5,5,5,5,5}
```

For every index:

* Left scan → goes full length
* Right scan → goes full length

So roughly:

```
n times → scanning ~n elements → n²
```

---

## ✅ Final answer

**Time Complexity = O(n²)**
**Space Complexity = O(1)** (no extra data structures)
