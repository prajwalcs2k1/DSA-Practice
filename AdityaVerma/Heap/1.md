# Time Complexity Analysis

Let `N` be the number of elements in the heap.

---

# 1. `insert(int val)`

### Operation:

* insert element at end
* perform heapify-up

In worst case, the element moves from leaf to root.

Height of heap:

h = \log_2 N

So maximum swaps/comparisons:

```text
O(log N)
```

### Time Complexity

| Case       | Complexity |
| ---------- | ---------- |
| Best Case  | `O(1)`     |
| Worst Case | `O(log N)` |

---

# 2. `top()`

You simply return:

```cpp id="5lx88n"
heap[0]
```

### Time Complexity

```text
O(1)
```

### Space Complexity

```text
O(1)
```

---

# 3. `deleteRoot()`

### Operations:

1. swap root with last element
2. pop last element
3. heapify-down

In worst case, root travels from top to bottom.

Maximum levels:

h = \log_2 N

### Time Complexity

| Case       | Complexity |
| ---------- | ---------- |
| Best Case  | `O(1)`     |
| Worst Case | `O(log N)` |

---

# 4. Space Complexity of Heap

You store all elements inside:

```cpp id="98t79v"
vector<int> heap;
```

If there are `N` elements:

### Space Complexity

```text
O(N)
```

---

# 5. Auxiliary Space (Extra Memory)

Your algorithms use only:

* indices
* temporary variables

No recursion.

### Extra Space

```text
O(1)
```

---

# Final Complexity Table

| Operation          | Time Complexity | Space Complexity |
| ------------------ | --------------- | ---------------- |
| `insert()`         | `O(log N)`      | `O(1)` auxiliary |
| `top()`            | `O(1)`          | `O(1)`           |
| `deleteRoot()`     | `O(log N)`      | `O(1)` auxiliary |
| Total Heap Storage | —               | `O(N)`           |

---

# One Small Note About `vector`

`vector::push_back()` is:

* amortized `O(1)`
* occasionally `O(N)` during resizing

But in heap analysis we usually consider:

* insertion dominated by heapify-up
* therefore overall insertion complexity remains:

```text
O(log N)
```
