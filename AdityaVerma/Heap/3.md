# Max Heap Construction using Heapify Down (Build Heap Algorithm)

## Problem Statement

Write a C++ program to convert a normal array into a **Max Heap** using the **Heapify Down** approach.

A Max Heap is a Complete Binary Tree where:

- Every parent node is greater than or equal to its children.
- The maximum element is always present at the root.

---

# Example

## Input Array

```text
4 10 3 5 1
````

## Output Heap Array

```text
10 5 3 4 1
```

This array representation satisfies the Max Heap property.

---

# Understanding Heap Representation in Arrays

A Heap is generally stored using arrays.

For any index `i`:

| Node        | Formula   |
| ----------- | --------- |
| Left Child  | `2*i + 1` |
| Right Child | `2*i + 2` |
| Parent      | `(i-1)/2` |

---

# What is Heapify Down?

Heapify Down is the process of:

1. Comparing a parent with its children
2. Finding the largest element
3. Swapping if required
4. Continuing downward until heap property is restored

---

# Step-by-Step Explanation

---

## Step 1: Find Largest Element

```cpp
int largestInd = index;
```

Initially assume current node is largest.

---

## Step 2: Find Child Indices

```cpp
int leftChildInd = 2*index+1;
int rightChildInd = 2*index+2;
```

These formulas map array indices to binary tree structure.

---

## Step 3: Compare Left Child

```cpp
if((leftChildInd < n) &&
   (arr[leftChildInd] > arr[largestInd]))
```

Check:

* left child exists
* left child is greater than current largest

If true:

```cpp
largestInd = leftChildInd;
```

---

## Step 4: Compare Right Child

```cpp
if((rightChildInd < n) &&
   (arr[rightChildInd] > arr[largestInd]))
```

Update largest element if right child is bigger.

---

## Step 5: Swap if Needed

```cpp
if(largestInd != index)
```

If current node is not largest:

```cpp
swap(arr[largestInd], arr[index]);
```

Now heap property may be violated below,
so recursively heapify downward.

---

## Step 6: Recursive Heapify

```cpp
heapify(arr, n, largestInd);
```

Continue fixing subtree.

---

# Why Start From Last Non-Leaf Node?

Leaf nodes already satisfy heap property.

So we only process non-leaf nodes.

Formula:

```cpp
int nonLeafInd = (n/2)-1;
```

---

# Build Heap Process

```cpp
for(int i=nonLeafInd; i>=0; i--){
    heapify(arr, n, i);
}
```

We process nodes bottom-up.

This guarantees:

* child subtrees become heaps first
* then parent nodes are fixed

# Time Complexity Analysis

## Heapify Function

Worst-case:

* element may move from root to leaf

Height of heap:

```text
O(log N)
```

So single heapify operation:

```text
O(log N)
```

---

# Why Overall Build Heap is O(N)?

At first glance:

```text
N nodes × O(log N)
= O(N log N)
```

But this is incorrect.

Reason:

* most nodes are near leaves
* most heapify operations are very small

---

# Mathematical Analysis

| Height From Bottom | Number of Nodes | Work Per Node |
| ------------------ | --------------- | ------------- |
| 0                  | N/2             | 0             |
| 1                  | N/4             | 1             |
| 2                  | N/8             | 2             |
| 3                  | N/16            | 3             |

Total work:

```text
(N/4)*1 +
(N/8)*2 +
(N/16)*3 + ...
```

Factoring N:

```text
N * (1/4 + 2/8 + 3/16 + ...)
```

This infinite series evaluates to a constant.

Therefore:

```text
Overall Time Complexity = O(N)
```

---

# Space Complexity

## Input Array Storage

```text
O(N)
```

because array stores N elements.

---

## Recursive Stack Space

Heapify recursion depth:

```text
O(log N)
```

So auxiliary recursive stack space:

```text
O(log N)
```

---

# Final Complexity Summary

| Operation             | Complexity |
| --------------------- | ---------- |
| Single Heapify        | `O(log N)` |
| Build Heap            | `O(N)`     |
| Array Storage         | `O(N)`     |
| Recursive Stack Space | `O(log N)` |

# Important Interview Points

## Repeated Insertions

If heap is built using repeated insertion:

```text
O(N log N)
```

---

## Bottom-Up Heap Construction

Using Heapify Down:

```text
O(N)
```

This is the optimal approach used internally in libraries.
