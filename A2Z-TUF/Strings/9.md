# Maximum Nesting Depth of Parentheses (C++)

## 📌 Problem Statement

Given a **valid parentheses string** `s`, determine the **maximum nesting depth**.

**Nesting depth** is defined as the maximum number of `'('` parentheses that are open at any point in the string.

### Example

```
Input  : "((1+(2*3))+((8)/4))"
Output : 3
```

---

## 🧠 Key Observation

* Every `'('` increases the nesting level by 1
* Every `')'` decreases the nesting level by 1
* The **maximum value reached** during this process is the answer

---

## 🚀 Approach 1: Optimized (Single Pass)

### 💡 Idea

* Traverse the string once
* Maintain:

  * `openParenthesis` → current depth
  * `mxDepth` → maximum depth seen so far
* Increment depth on `'('`
* Decrement depth on `')'`
* Update max depth whenever depth increases

---

### ✅ Code Logic

```cpp
if(s[i] == '('){
    openParenthesis++;
    mxDepth = max(mxDepth, openParenthesis);
}else if(s[i] == ')'){
    openParenthesis--;
}
```

---

### ⏱ Complexity Analysis

* **Time Complexity:** `O(n)`
* **Space Complexity:** `O(1)`

---

### 🏆 Why This Is Optimal

* Every character must be examined at least once
* No extra data structures used
* Fastest possible solution for this problem

---

## 🐌 Approach 2: Brute Force

### 💡 Idea

For every index `i` in the string:

1. Consider the substring `s[0...i]`
2. Count:

   * Number of `'('`
   * Number of `')'`
3. Depth at index `i` = `open - close`
4. Keep track of the maximum depth across all indices

---

### ⏱ Complexity Analysis

* **Time Complexity:** `O(n²)`
* **Space Complexity:** `O(1)`

---

### ❌ Why It’s Inefficient

* Recalculates counts for each prefix
* Does redundant work
* Becomes slow for large inputs

---

## 🔍 Comparison Summary

| Approach    | Time  | Space | Notes                         |
| ----------- | ----- | ----- | ----------------------------- |
| Brute Force | O(n²) | O(1)  | Easy to think of, inefficient |
| Optimized   | O(n)  | O(1)  | Best & recommended            |

---

## 🎯 Important Assumptions

* Input string is **valid**
* If invalid parentheses were allowed, extra checks would be required to avoid negative depth

---

## 📚 Revision Tips

* This problem is about **prefix maximum**
* Brute force → recompute every prefix
* Optimized → maintain a **running counter**
* Similar pattern appears in:

  * Valid Parentheses
  * Score of Parentheses
  * Remove Outermost Parentheses

---

## ✅ Final Takeaway

> If a problem asks for **maximum depth / balance / prefix value**,
> try to **track it dynamically in one pass** instead of recomputing.
