## 1 What rotation REALLY is (ignore code for a moment)

Rotation is **not moving elements**.
Rotation is **cut + reorder two blocks**.

### Right rotate by `k`

```
Original:  [ A | B ]
Where:
A = first n-k elements
B = last  k elements

Result:    [ B | A ]
```

### Left rotate by `k`

```
Original:  [ A | B ]
Where:
A = first k elements
B = remaining n-k elements

Result:    [ B | A ]
```

👉 Rotation = **swap two contiguous blocks while preserving order inside each block**

---

## 2 What reversing ACTUALLY does (key insight 🔑)

Reversing is a **tool to swap blocks while preserving internal order**.

This identity is the heart of everything:

```
reverse(A + B)
= reverse(B) + reverse(A)
```

This is the **only reason reverse method works**.

---


## 3 So WHY is the code different?

Because **the blocks are different**.

| Rotation | Blocks         |
| -------- | -------------- |
| Right    | A = n-k, B = k |
| Left     | A = k, B = n-k |

The reverse operations must match **how you cut the array**.

---

## 4 The ONE-LINE mental model (remember this forever)

> 🔑 **Reversing lets you swap two blocks without disturbing their internal order**

Everything else is just *where you cut the blocks*.

---

## 5 Code side-by-side (clear comparison)

### Right rotate by `k`

```cpp
k %= n;
reverse(nums.begin(), nums.end());
reverse(nums.begin(), nums.begin() + k);
reverse(nums.begin() + k, nums.end());
```

### Left rotate by `k`

```cpp
k %= n;
reverse(nums.begin(), nums.begin() + k);
reverse(nums.begin() + k, nums.end());
reverse(nums.begin(), nums.end());
```

Different order → same principle.

---

## 6 Why reverse method is SO powerful

* O(n) time
* O(1) space
* No cycles, no GCD
* Very interview-friendly
* Elegant mathematics underneath

---

## 7 Deep connection (advanced insight 🧠)

Reverse method is actually:

* Applying **permutation inverses**
* Using the property of **involutions** (reverse is its own inverse)
* Avoiding explicit cycle tracking

It’s still a permutation trick — just disguised.
